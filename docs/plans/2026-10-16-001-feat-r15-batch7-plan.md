# R15 batch 7: a context size for Claude Code, and a `doctor` repair for a stale proxy URL

Goal: close the two open R15 batch 7 items in `TODO.md`.

1. `init`'s Claude Code integration writes no context size, so Claude Code sizes every
   non-`claude-` model at 200,000 and compacts far early.
2. `doctor` has no check for a tool config that still names a port the proxy no longer
   listens on, so nothing can repair one.

Scope: `src/init/external/tools/claude_code.rs`, `src/init/doctor.rs`, the small read/rewrite
helper in `src/init/external/`, `docs/usage.md`, `CHANGELOG.md`, `TODO.md`. Two units, two
sessions, no shared files.

## Decisions

- **D1 — the env var is `CLAUDE_CODE_MAX_CONTEXT_TOKENS`.** Verified against the installed
  Claude Code 2.1.301 binary (the string is there) and code.claude.com/docs/en/env-vars:
  "Override the context window size Claude Code assumes for the active model … Use this when
  routing to a model through `ANTHROPIC_BASE_URL` whose context window does not match the
  built-in size for its name". docs/en/model-config adds: for an unrecognized ID that does not
  start with `claude-` and carries no `[1m]` suffix the variable takes effect on its own — which
  is every model name we write (`qwen3-coder-30b`, `flash-next-halogen@dual-256k`).
- **D2 — the number is the launch window minus the output room Claude Code does not already keep
  for itself.** Claude Code compacts at assumed window − 33,000 and refuses to send at window
  − 23,000, so its largest prompt is 23,000 under what we write. The engine has to fit the same
  generation inside the launch window, and we declare a 32,000-token output cap everywhere else
  (`PatchModel::declared_output`). So write `context − saturating_sub(output, 20_000)`:
  262,144 ctx → output 32,000 → **250,144**, whose send ceiling (227,144) stays inside what
  Halogen accepts at that window (229,376). A model with no known context falls back to
  `DEFAULT_CONTEXT_WINDOW` (32,000), gets `output` 16,000, and is written unchanged.
- **D3 — only Claude Code needs this.** OpenCode already gets `limit.context`, Codex
  `model_context_window`, pi.dev `contextWindow`, Zed `max_tokens`; OpenCode compacts at
  `context − output` on its own. Aider, Continue.dev and `env-sh` have no window field to write.
- **D4 — the `doctor` repair rewrites the URL in place, it does not re-run `init`.** Re-applying
  a patcher would also rewrite the model list to the current default preset, which is a bigger
  change than the one broken value. A textual replace of the stale `http://host:port` — host
  must match the live proxy's host — touches only the URL and works uniformly for the generated
  `.sh` files, JSON, TOML and YAML configs alike. The path portion each file already carries
  (`/v1` for OpenAI-shape tools, none for Claude Code) is left alone; only host and port change.
- **D5 — the check only runs when a daemon's proxy is actually listening.**
  `proxy_url::from_running_daemon()` already returns the live base in 2 s without spawning a
  daemon. With no live proxy there is nothing to compare against, and `doctor` must never spawn
  one. No finding, no fix, silent.
- **D6 — new finding and fix ids are additive, so bump `DOCTOR_JSON_SCHEMA_VERSION` 2 → 3.**

- Add a pure helper, unit-testable:
  `fn declared_window(context: u64, output: u64) -> u64 { context.saturating_sub(output.saturating_sub(20_000)) }`
- In `raw_body`, inside the same arm that pins `ANTHROPIC_MODEL` / `ANTHROPIC_SMALL_FAST_MODEL`
  (so an embedder or no-model context still writes neither), add

  `declared_context()` and `declared_output()`.
- Extend the module header bullet list with what the var does (one line, plain).
- Tests in the same file: the value for a 262,144-context model is 250,144; a small/unknown
  context is written unchanged; the var is absent for an embedder and for no models at all.
- Do not touch `docs/`, `CHANGELOG.md` or `TODO.md` — U2 owns those, including the doc line for
  this unit.

### U2 — `doctor` finds a dead proxy port in a tool config and repairs it (lane `impl-2`)

Owns `src/init/doctor.rs`, a new helper under `src/init/external/` (keep it small; its own
module file plus whatever `src/init/external/mod.rs` export it needs), `docs/usage.md`,
`CHANGELOG.md`, `TODO.md`, and this plan's tick marks. Do not edit
`src/init/external/tools/claude_code.rs` — another session is editing it right now.

Check:

- `FindingId::ToolConfigStaleUrl` → `tool_config_stale_url`, `Severity::Warning`,
  `fix_action() → Some(FixId::ToolConfigProxyUrl)`; `FixId::ToolConfigProxyUrl` (serde
  `tool_config_proxy_url`), action verb `rewrite url`. Manual `fix_hint()` for the case the
  repair is withheld: "re-run `llamastash init --integrations <ids>`".
- Run it from `run()` (async, `src/init/doctor.rs` ~1083) after the report is built and before
  `apply_fixes`, so `--fix` and `--dry-run` pick the repair up the way the existing repairs do.
  Get the live base from `proxy_url::from_running_daemon()`; skip the whole check when it
  returns `None` (D5).
- For every `tools::registered()` patcher plus its companions, take the first existing path
  among `default_path()` and `alt_paths()`. Scan the file text for `http://host:port` URLs
  (terminate at a quote, whitespace, or `<`); a URL is stale when its host equals the live
  proxy host and its port is not the live port. One finding per file naming the path, the stale
  URL and the live one. Nothing secret in the message (`safe_to_log` stays true).

Repair:

- Rewrite every stale URL in the file to the live `host:port`, keeping the file's own path
  suffix; leave any URL whose host differs. `--dry-run` → `WouldApply`, write error → `Failed`,
  one `FixReport` per file.

Tests (proportionate, in the module where the code lands):

- stale port detected, matching port not, a foreign host on the same port not;
- the repair rewrites only the stale URL and leaves the rest of the file byte-identical, and it
  does not touch a file whose URL host differs;
- dry-run proposes and writes nothing;
- `--json` carries `fix: "tool_config_proxy_url"` on the finding and the ledger entry;
- schema version is 3.
